Chapter 51: ROS 2 services

Ask and Answer Services, Requests and Responses in ROS 2

Topics send messages one way. Services work like a question and an answer: one node asks, another node does the job and replies. This page builds the idea step by step, with a face-following robot and an integral calculator as examples. Every section has something to move or play. The numbers are examples, chosen to be easy to read.

Two ways for nodes to talk

So far nodes have talked through topics. ROS 2 also offers a second way to communicate, called services. A service is a node that offers a function to other nodes, using a request and a response instead of publishing and subscribing. Use Next and Back, the sliders, the buttons and Play. Key idea. A service is a node that offers functionality to other nodes. It uses a request and response protocol, instead of the publisher and subscriber protocol used with topics.

The face-following robot: why a copy is a problem

Here is an example: a node finds faces in the camera stream of a robot and makes the robot follow them. Later, a second node needs the very same face recognition function. Use Next and Back, the sliders, the buttons and Play. Point at a coloured word to light up its part of the picture.

Key idea. Copying code that does the same job into several places is always a bad idea. Every change, a fix, a faster algorithm or a new library, has to be made in each copy, and each copy has to be tested.

One service server, many clients

The fix: put the function in one node, a service server, and let every node that needs it ask for it. Use Next and Back, the sliders, the buttons and Play. Point at a coloured word to light up its part of the picture.

Inside the messages: request and response

The node that needs the function is the client. It sends a request message, which can carry data, and gets a response message with the result. Use Next and Back, the sliders, the buttons and Play. Point at a coloured word to light up its part of the picture.

Key idea. The request carries the input the server needs, like a camera frame. The server runs its logic and puts its output, like the position of the face, in the response, which goes back to the client.

06

Waiting without stopping

The communication starts with a request. The server processes it while the client goes on with its own work, and when the server is done, the client is notified. Use Next and Back, the sliders, the buttons and Play. Point at a coloured word to light up its part of the picture.

Key idea. The client does not need to stand still while the server works. It continues its own work, waits for the response, is notified when it arrives, and then uses the result.

07

Summary and quiz

Key takeaways

  1. A service is a second way for ROS 2 nodes to communicate, different from topics. It uses a request and a response.
  2. A service server is a node that offers a function to other nodes, so the code is written, maintained, tested and optimised in one place.
  3. Copying the same function into several nodes is a bad idea: every change must be repeated and tested in each copy.
  4. The service client sends a request message. The request can carry data the server needs, for example a camera frame.
  5. The server runs its logic and sends a response message with the result, for example the position of a face, back to the client that asked.
  6. Any node that needs the same function can send its own request and gets its own response, as with a server that calculates an integral.
  7. While the server processes a request, the client can continue its own work. When the response arrives, the client is notified and uses the result.
