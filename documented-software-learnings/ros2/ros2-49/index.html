Simple TF2 Static Broadcaster

Introduction

In ROS 2, a transform describes where one coordinate frame sits relative to another. A static transform is one that never changes, such as a sensor bolted onto a robot body. It is published once on the /tf_static topic and stays valid for as long as the node runs.

In this chapter we write a small Python node, simple_tf_kinematics, that publishes one static transform between two frames: bumperbot_base (the parent) and bumperbot_top (the child), placed 0.3 above it along the Z axis with no rotation. We then build the package, run the node, inspect /tf_static and view both frames in rviz2.

FieldValue
Parent frame (header.frame_id)bumperbot_base
Child frame (child_frame_id)bumperbot_top
Translation (x, y, z)0.0, 0.0, 0.3
Rotation quaternion (x, y, z, w)0.0, 0.0, 0.0, 1.0 (no rotation)

Create the Node

Create the Python file

In the workspace, open src, then the bumperbot_py_examples package folder, then the inner bumperbot_py_examples folder, and create a new Python file named:

simple_tf_kinematics.py

Write the code

Inside simple_tf_kinematics.py, add:

import rclpy
from rclpy.node import Node
from tf2_ros.static_transform_broadcaster import StaticTransformBroadcaster
from geometry_msgs.msg import TransformStamped


class SimpleTfKinematics(Node):

    def __init__(self):
        super().__init__("simple_tf_kinematics")

        self.static_tf_broadcaster_ = StaticTransformBroadcaster(self)

        self.static_transform_stamped_ = TransformStamped()
        self.static_transform_stamped_.header.stamp = self.get_clock().now().to_msg()
        self.static_transform_stamped_.header.frame_id = "bumperbot_base"
        self.static_transform_stamped_.child_frame_id = "bumperbot_top"
        self.static_transform_stamped_.transform.translation.x = 0.0
        self.static_transform_stamped_.transform.translation.y = 0.0
        self.static_transform_stamped_.transform.translation.z = 0.3
        self.static_transform_stamped_.transform.rotation.x = 0.0
        self.static_transform_stamped_.transform.rotation.y = 0.0
        self.static_transform_stamped_.transform.rotation.z = 0.0
        self.static_transform_stamped_.transform.rotation.w = 1.0

        self.static_tf_broadcaster_.sendTransform(self.static_transform_stamped_)

        self.get_logger().info("Publishing static transform between %s and %s" %
                      (
                        self.static_transform_stamped_.header.frame_id,
                        self.static_transform_stamped_.child_frame_id
                      ))


def main():
    rclpy.init()

    simple_tf_kinematics = SimpleTfKinematics()
    rclpy.spin(simple_tf_kinematics)

    simple_tf_kinematics.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()

The transform is sent once, inside __init__. The node then only needs to keep spinning so that it stays alive and the transform remains available on /tf_static.

Register the Node in the Package

Add the entry point in setup.py

Open setup.py in the bumperbot_py_examples package and add the following line to the console_scripts list under entry_points. Keep a comma after the previous entry.

'simple_tf_kinematics = bumperbot_py_examples.simple_tf_kinematics:main'

Declare the dependencies in package.xml

Open package.xml and add these two lines next to the other exec_depend entries. They tell ROS 2 that the node needs tf2_ros (the broadcaster) and geometry_msgs (the TransformStamped message).

<exec_depend>tf2_ros</exec_depend>
<exec_depend>geometry_msgs</exec_depend>

Explanation

Use the interactive visualizer below to walk through the code line by line, see how the pieces connect, and follow the build and run steps.

Build and Run

Build the workspace

Open a terminal and go to the workspace:

cd bumperbot_ws

Then build it:

colcon build

Wait for the build to finish successfully.

Run the node

Open a second terminal and source the workspace:

. install/setup.bash

Then start the node:

ros2 run bumperbot_py_examples simple_tf_kinematics

Inspect the Transform

List the topics

In a third terminal, list the active topics:

ros2 topic list

The output contains:

/parameter_events
/rosout
/tf_static

Echo /tf_static

To see the message itself, run:

ros2 topic echo /tf_static

The message shows the parent frame bumperbot_base, the child frame bumperbot_top, a translation of 0.3 on Z and an identity rotation (w: 1.0), exactly the values set in the code.

Visualize in rviz2

Launch rviz2

In another terminal, start rviz2:

rviz2

Set the fixed frame

In the Displays panel, change Fixed Frame to bumperbot_base.

Add the TF display

Click Add, choose TF from the list of display types and confirm. Two sets of axes appear in the 3D view.

Show the frame names

Expand the TF settings and tick Show Names. The labels bumperbot_top and bumperbot_base appear next to their axes, with bumperbot_top above the base.
