Introduction to Turtlesim

Turtlesim is a simple 2D simulation tool available in ROS 2. It allows us to move a turtle around a virtual environment and understand some of the fundamental concepts used in robotics.

In this lesson, we will use Turtlesim to explore:

  • ROS 2 nodes and topics
  • Publishing velocity commands
  • Understanding a robot’s pose in 2D
  • Using rqt_graph to visualize communication between nodes
  • Using a ROS 2 service to spawn another turtle
  • Remapping topics to control different turtles

Although Turtlesim is a simple application, the same communication concepts are relevant when working with more complex robots such as our BumperBot.

Start Turtlesim

First, we need to start the Turtlesim simulation.

Open a terminal and run:

ros2 run turtlesim turtlesim_node

What does this command do?

The command starts the turtlesim_node executable from the turtlesim package.

ros2 run
    │
    ├── turtlesim
    │      Package name
    │
    └── turtlesim_node
           Executable name

After running the command, a new window will appear containing a turtle inside a 2D environment.

This window represents the environment in which our turtle will move.

Control the Turtle Using the Keyboard

Now we will start another node that allows us to control the turtle using the keyboard.

Open a new terminal while keeping the Turtlesim window running.

Run:

ros2 run turtlesim turtle_teleop_key

The turtle_teleop_key node allows us to control the turtle using the keyboard. Make sure the terminal running this node is focused when you press the movement keys.

Try moving the turtle around the environment.

What is happening behind the scenes?

Two ROS 2 nodes are now running:

┌─────────────────────┐
│   turtle_teleop_key │
│                     │
│ Reads keyboard input│
└──────────┬──────────┘
           │
           │ Velocity commands
           ▼
┌─────────────────────┐
│    turtlesim_node   │
│                     │
│ Moves the turtle    │
└─────────────────────┘

The teleoperation node sends velocity commands, and the Turtlesim node receives those commands and moves the turtle accordingly.

In the following sections, we will inspect this communication directly.

List the Available ROS 2 Topics

Open another terminal and run:

ros2 topic list

You should see several topics, including:

/parameter_events
/rosout
/turtle1/cmd_vel
/turtle1/color_sensor
/turtle1/pose

What Are These Topics?

A ROS 2 topic allows nodes to communicate by publishing and receiving messages.

Let’s look at the most relevant topics in this example.

TopicPurpose
/turtle1/cmd_velCarries velocity commands for the turtle
/turtle1/posePublishes the turtle’s current pose and velocity
/turtle1/color_sensorProvides the turtle’s color-sensor information
/rosoutCarries ROS 2 logging messages
/parameter_eventsReports parameter-related events

The topic that we will use first is:

/turtle1/cmd_vel

This is the topic through which the teleoperation node sends velocity commands to the turtle.

Understand the communication

turtle_teleop_key
       │
       │ Publishes velocity commands
       ▼
/turtle1/cmd_vel
       │
       │ Receives messages
       ▼
turtlesim_node
       │
       ▼
Turtle moves

Key idea: The teleoperation node does not move the turtle directly. It publishes messages, and the Turtlesim node uses those messages to determine the turtle’s movement.

Visualize Node Communication Using rqt_graph

The terminal allows us to list the available topics, but it does not show the complete communication structure visually.

ROS 2 provides another useful tool: rqt_graph.

Open a new terminal and run:

ros2 run rqt_graph rqt_graph

Understand the Graph

Inside rqt_graph, you can choose to display the active nodes, topics, or their connections.

For example, when both Turtlesim and keyboard teleoperation are running, the graph should show the relationship between:

  • /teleop_turtle
  • /turtlesim
  • /turtle1/cmd_vel

The communication can be represented as:

/teleop_turtle
       │
       │ Publisher
       ▼
/turtle1/cmd_vel
       │
       │ Subscriber
       ▼
/turtlesim

The graph makes it easier to understand how the nodes communicate.

What Happens When We Stop Teleoperation?

Go to the terminal running:

ros2 run turtlesim turtle_teleop_key

Press:

Ctrl + C

This stops the teleoperation node.

Return to rqt_graph and refresh the graph.

Now, the teleoperation node should disappear because it is no longer running. The Turtlesim node remains active.

This demonstrates that the graph reflects the nodes and communication relationships currently available in the ROS 2 system.

Publish Velocity Commands Manually

Start by typing:

ros2 topic pub /turtle1/cmd_vel geometry_msgs/msg/Twist

Press Tab twice to explore the available message completions.

You can use the terminal’s autocompletion to generate a template for the Twist message.

The message will contain fields similar to:

ros2 topic pub /turtle1/cmd_vel geometry_msgs/msg/Twist "'linear:
  x: 0.0
  y: 0.0
  z: 0.0
angular:
  x: 0.0
  y: 0.0
  z: 0.0
'"

This is the structure of the message we will publish.

Rotate the Turtle in Place

First, let’s make the turtle rotate without moving forward.

We will set all the linear velocities to zero and set angular.z to 1.0.

Run:

ros2 topic pub /turtle1/cmd_vel geometry_msgs/msg/Twist "linear:
  x: 0.0
  y: 0.0
  z: 0.0
angular:
  x: 0.0
  y: 0.0
  z: 1.0
"

Since the linear velocity is zero, the turtle does not move forward. Instead, it rotates in place.

Move Forward While Rotating

Run:

ros2 topic pub /turtle1/cmd_vel geometry_msgs/msg/Twist "linear:
  x: 1.0
  y: 0.0
  z: 0.0
angular:
  x: 0.0
  y: 0.0
  z: 1.0
"

Now if we take x as 1 in linear

Now both linear and angular velocities are nonzero.

The turtle moves forward while changing its orientation, producing a circular path under these constant velocity commands.

Read the Turtle’s Pose

So far, we have sent commands to move the turtle.

Now let’s inspect the turtle’s current position and orientation.

Open a new terminal.

Run:

ros2 topic echo /turtle1/pose

This command subscribes to /turtle1/pose and prints the messages being published on that topic.

You should see output similar to:

x: 10.485991477966309
y: 4.498754501342773
theta: 1.1740517616271973
linear_velocity: 1.0
angular_velocity: 1.0
---
x: 10.491937637329102
y: 4.513608455657959
theta: 1.190051794052124
linear_velocity: 1.0
angular_velocity: 1.0
---

Your values will be different depending on the turtle’s position and movement.

Understanding the Pose Message

Spawn Another Turtle

So far, we have been working with turtle1.

Turtlesim also allows us to create another turtle in the same environment using a ROS 2 service.

Now we will use the /spawn service to create turtle2.

Run:

ros2 service call /spawn turtlesim/srv/Spawn "x: 4.0
y: 4.0
theta: 0.0
name: 'turtle2'"

This requests that Turtlesim create another turtle with:

FieldValueMeaning
x4.0Horizontal starting position
y4.0Vertical starting position
theta0.0Initial orientation
nameturtle2Name assigned to the new turtle

Remember that these coordinates use the Turtlesim coordinate system, whose origin is in the bottom-left corner.

What Changed?

After spawning the second turtle, Turtlesim provides additional topics associated with it.

For example:

/turtle2/cmd_vel
/turtle2/pose
/turtle2/color_sensor

This means that the second turtle has its own velocity-command topic and pose topic.

Conceptually:

turtle1/cmd_vel  ──► turtle1

turtle2/cmd_vel  ──► turtle2

We can therefore control the two turtles independently by publishing to their respective topics.

to control another turtle2 quit current teleop and run

Control the Second Turtle Using Keyboard Teleoperation

The keyboard teleoperation node normally publishes to:

/turtle1/cmd_vel

But we want to use it to control turtle2.

Instead of modifying the teleoperation node’s source code, we can remap its topic when we start it.

First, stop the existing teleoperation node with Ctrl + C.

Now run:

ros2 run turtlesim turtle_teleop_key --ros-args --remap turtle1/cmd_vel:=turtle2/cmd_vel

Think of it as:

Default topic
/turtle1/cmd_vel
        │
        │ Remap
        ▼
/turtle2/cmd_vel

The teleoperation node now publishes its velocity commands to the second turtle’s topic.

Key idea

Remapping changes which topic a node uses without requiring you to modify its source code.

This is a useful feature in ROS 2 because it allows the same node to be reused with different topics and different parts of a robot system.
