Launch the Simple Speed Controller

Introduction

In the previous chapter, we developed a Python ROS 2 node named simple_controller.py that converts the robot’s linear and angular velocity commands into individual wheel velocities.

Now, we will add this Python node to our existing ROS 2 launch file and test it in the Gazebo simulation.

Our launch file will:

  • Start the joint_state_broadcaster.
  • Start the simple_velocity_controller.
  • Launch the Python Simple Controller node.
  • Pass the wheel radius and wheel separation parameters to the node.

After launching the controller, we will publish velocity commands manually and observe how the BumperBot moves in Gazebo.

Open the Existing Launch File

Open the bumperbot_controller package in Visual Studio Code.

Navigate to the launch folder and open the existing file:

controller.launch.py

We will modify this file to launch our Python Simple Controller.

Write the Code

from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch_ros.actions import Node
from launch.substitutions import LaunchConfiguration


def generate_launch_description():


    wheel_radius_arg = DeclareLaunchArgument(
        "wheel_radius",
        default_value="0.033",
    )
    wheel_separation_arg = DeclareLaunchArgument(
        "wheel_separation",
        default_value="0.17",
    )

    wheel_radius = LaunchConfiguration("wheel_radius")
    wheel_separation = LaunchConfiguration("wheel_separation")

    joint_state_broadcaster_spawner = Node(
        package="controller_manager",
        executable="spawner",
        arguments=[
            "joint_state_broadcaster",
            "--controller-manager",
            "/controller_manager",
        ],
    )

    simple_controller = Node(
        package="controller_manager",
        executable="spawner",
        arguments=["simple_velocity_controller",
                "--controller-manager",
                "/controller_manager"
        ]
    )

    simple_controller_py = Node(
        package="bumperbot_controller",
        executable="simple_controller.py",
         parameters=[
                    {"wheel_radius": wheel_radius,
                    "wheel_separation": wheel_separation,
                    }]
    )

    return LaunchDescription(
        [
            wheel_radius_arg,
            wheel_separation_arg,
            joint_state_broadcaster_spawner,
            simple_controller,
            simple_controller_py
        ]
    )

Build the Workspace

cd bumperbot_ws

Run the following command:

colcon build

Wait for the build to complete successfully.

Start the Gazebo Simulation

Open another terminal and source the workspace:

. install/setup.bash

Now start the Gazebo simulation:

ros2 launch bumperbot_description gazebo.launch.py

Wait for the BumperBot to appear in Gazebo.

Inspect the Available Launch Arguments

Open another terminal and source the workspace:

. install/setup.bash

Before launching the controller, let's inspect the available launch arguments.

ros2 launch bumperbot_controller controller.launch.py --show-args

You should see the following arguments:

'wheel_radius':
    no description given
    (default: '0.033')

'wheel_separation':
    no description given
    (default: '0.17')

These arguments allow us to configure the wheel dimensions when launching the controller.

Launch the Python Controller

Now, start the controller system.

Run:

ros2 launch bumperbot_controller controller.launch.py

This will start:

  • The Joint State Broadcaster.
  • The Simple Velocity Controller.
  • The Python Simple Controller node.

The Python node will receive robot velocity commands, convert them into individual wheel velocities, and publish the results to the wheel controller.

Inspect the Available ROS 2 Topics

Once the controller system has started, open another terminal.

Source the workspace:

cd bumperbot_ws
source install/setup.bash

Run:

ros2 topic list

You should find topics similar to:

/bumperbot_controller/cmd_vel
/clock
/controller_manager/activity
/joint_states
/robot_description
/simple_velocity_controller/commands
/tf
/tf_static

The two most important topics for our test are:

TopicPurpose
/bumperbot_controller/cmd_velReceives the robot's linear and angular velocity commands.
/simple_velocity_controller/commandsReceives the calculated wheel velocity commands.

Our Python controller subscribes to the first topic and publishes the calculated wheel velocities to the second topic.

Publish Velocity Commands Manually

Open a new terminal and start typing:

ros2 topic pub /bumperbot_controller/cmd_vel geometry_msgs/msg/TwistStamped 'h

Press Tab twice to view the available message structure.

You can also use Tab autocompletion after entering the message argument to generate an empty message template.

The structure looks like this:

ros2 topic pub /bumperbot_controller/cmd_vel geometry_msgs/msg/TwistStamped 'header:
  stamp:
    sec: 0
    nanosec: 0
  frame_id: ''
twist:
  linear:
    x: 0.0
    y: 0.0
    z: 0.0
  angular:
    x: 0.0
    y: 0.0
    z: 0.0
'

Test 1, Perform an In-Place Rotation

First, let's make the robot rotate without moving forward.

For this, set:

Linear velocity  = 0.0 m/s

Angular velocity = 0.5 rad/s

Run the following command:

ros2 topic pub /bumperbot_controller/cmd_vel geometry_msgs/msg/TwistStamped 'header:
  stamp:
    sec: 0
    nanosec: 0
  frame_id: ''
twist:
  linear:
    x: 0.0
    y: 0.0
    z: 0.0
  angular:
    x: 0.0
    y: 0.0
    z: 0.5
'

Observe the Gazebo simulation.

The robot should perform an in-place rotation.

What Happens to the Wheels?

During an in-place rotation:

  • The right wheel moves forward.
  • The left wheel moves backward.

The wheels rotate in opposite directions, allowing the robot to turn around its centre.

Test 2, Move Forward While Rotating

Now, let's make the robot move forward and rotate simultaneously.

Set the linear velocity along the X-axis to 1.0, while keeping the angular velocity at 0.5.

Run:

ros2 topic pub /bumperbot_controller/cmd_vel geometry_msgs/msg/TwistStamped 'header:
  stamp:
    sec: 0
    nanosec: 0
  frame_id: ''
twist:
  linear:
    x: 1.0
    y: 0.0
    z: 0.0
  angular:
    x: 0.0
    y: 0.0
    z: 0.5
'

The command now contains:

Linear velocity  = 1.0 m/s

Angular velocity = 0.5 rad/s

Observe the Gazebo simulation.

The robot should move forward while simultaneously rotating.

What Happens to the Wheels?

Both wheels contribute to forward movement, but they rotate at different speeds.

This difference in wheel speeds creates the turning motion while the robot continues moving forward.

Understand the Complete Controller Workflow

The complete process can be summarized as follows:

Robot Velocity Command
          |
          v
/bumperbot_controller/cmd_vel
          |
          v
Python Simple Controller
          |
          v
Extract Linear and Angular
Velocities
          |
          v
Differential Kinematics
          |
          v
Calculate Left and Right
Wheel Velocities
          |
          v
simple_velocity_controller/commands
          |
          v
Simple Velocity Controller
          |
          v
Robot Wheel Motion
          |
          v
Gazebo Simulation

This shows how a high-level velocity command is converted into individual wheel commands and finally produces movement in Gazebo.
