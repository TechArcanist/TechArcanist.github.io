ROS 2 Diff Drive Controller

Introduction

Now, we will explore an alternative approach using the Diff Drive Controller provided by the ROS 2 Controllers package.

A differential-drive robot uses two independently controlled wheels to move forward, backward, and rotate.

To control this type of robot, we need to convert its linear and angular velocity commands into individual wheel velocities.

We already implemented this in the Simple Controller. However, ROS 2 provides a built-in controller that performs this conversion and provides additional functionality for differential-drive robots.

Configure the Diff Drive Controller

Open the bumperbot_controller package in Visual Studio Code.

Navigate to the config folder and open:

bumperbot_controllers.yaml

We will modify this file to configure the Diff Drive Controller.

Write the Code

Inside bumperbot_controllers.yaml:

controller_manager:
  ros__parameters:
    update_rate: 100 # Hz
    use_sim_time: true

    bumperbot_controller:
      type: diff_drive_controller/DiffDriveController

    joint_state_broadcaster:
      type: joint_state_broadcaster/JointStateBroadcaster

    simple_velocity_controller:
      type: velocity_controllers/JointGroupVelocityController


bumperbot_controller:
  ros__parameters:
    type        : diff_drive_controller/DiffDriveController
    use_stamped_vel: true
    left_wheel_names  : ['wheel_left_joint']
    right_wheel_names : ['wheel_right_joint']

    publish_rate: 50.0               # default: 50
    pose_covariance_diagonal : [0.001, 0.001, 1.0e-3, 1.0e-3, 1.0e-3, 0.01]
    twist_covariance_diagonal: [0.001, 0.001, 1.0e-3, 1.0e-3, 1.0e-3, 0.01]

    wheel_separation : 0.17
    wheel_radius : 0.033

    wheel_separation_multiplier: 1.0
    left_wheel_radius_multiplier: 1.0
    right_wheel_radius_multiplier: 1.0

    # Velocity commands timeout [s], default 0.5
    cmd_vel_timeout: 0.5

    # Base frame_id
    base_frame_id: base_footprint #default: base_link

    # Publish limited velocity
    publish_limited_velocity: true

    # Publish wheel data
    publish_wheel_data: true

    # Publish to TF directly or not
    enable_odom_tf: true

    # Velocity and acceleration limits
    # Whenever a min_* is unspecified, default to -max_*
    linear:
      x:
        has_velocity_limits    : true
        max_velocity           : 1.0  # m/s
        min_velocity           : -0.5 # m/s
        has_acceleration_limits: true
        max_acceleration       : 0.8  # m/s^2
        min_acceleration       : -0.4 # m/s^2
        has_jerk_limits        : false
        max_jerk               : 5.0  # m/s^3
    angular:
      z:
        has_velocity_limits    : true
        max_velocity           : 1.7  # rad/s
        has_acceleration_limits: true
        max_acceleration       : 1.5  # rad/s^2
        has_jerk_limits        : false
        max_jerk               : 2.5  # rad/s^3


simple_velocity_controller:
  ros__parameters:
    joints:
      - wheel_left_joint
      - wheel_right_joint

Update the Controller Launch File

Now, we need to modify our existing launch file so that we can choose which controller to use when launching the robot.

Open:

launch/controller.launch.py

Write the Code

Inside launch/controller.launch.py:


from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, GroupAction
from launch_ros.actions import Node
from launch.substitutions import LaunchConfiguration
from launch.conditions import UnlessCondition, IfCondition


def generate_launch_description():

    use_sim_time_arg = DeclareLaunchArgument(
        "use_sim_time",
        default_value="True",
    )
    use_simple_controller_arg = DeclareLaunchArgument(
        "use_simple_controller",
        default_value="True",
    )
    wheel_radius_arg = DeclareLaunchArgument(
        "wheel_radius",
        default_value="0.033",
    )
    wheel_separation_arg = DeclareLaunchArgument(
        "wheel_separation",
        default_value="0.17",
    )

    use_sim_time = LaunchConfiguration("use_sim_time")
    use_simple_controller = LaunchConfiguration("use_simple_controller")
    wheel_radius = LaunchConfiguration("wheel_radius")
    wheel_separation = LaunchConfiguration("wheel_separation")

    joint_state_broadcaster_spawner = Node(
        package="controller_manager",
        executable="spawner",
        arguments=[
            "joint_state_broadcaster",
            "--controller-manager",
            "/controller_manager",
        ],
    )

    wheel_controller_spawner = Node(
        package="controller_manager",
        executable="spawner",
        arguments=[
            "bumperbot_controller",
            "--controller-manager",
            "/controller_manager",
        ],
        condition=UnlessCondition(use_simple_controller),
    )

    simple_controller = GroupAction(
        condition=IfCondition(use_simple_controller),
        actions=[
            Node(
                package="controller_manager",
                executable="spawner",
                arguments=[
                    "simple_velocity_controller",
                    "--controller-manager",
                    "/controller_manager",
                ],
            ),
            Node(
                package="bumperbot_controller",
                executable="simple_controller.py",
                parameters=[
                    {
                        "wheel_radius": wheel_radius,
                        "wheel_separation": wheel_separation,
                        "use_sim_time": use_sim_time,
                    }
                ],
            ),
        ],
    )

    return LaunchDescription(
        [
            use_sim_time_arg,
            use_simple_controller_arg,
            wheel_radius_arg,
            wheel_separation_arg,
            joint_state_broadcaster_spawner,
            wheel_controller_spawner,
            simple_controller,
        ]
    )

Build the Workspace

After updating the YAML configuration and launch file, open a terminal and navigate to your workspace:

cd bumperbot_ws

Run the following command:

colcon build

Wait for the build to complete successfully.

Start the Gazebo Simulation

Open another terminal and source the workspace:

. install/setup.bash

Now start the Gazebo simulation:

ros2 launch bumperbot_description gazebo.launch.py

Wait for the BumperBot to appear in Gazebo.

Inspect the Available Launch Arguments

Open another terminal and source the workspace:

cd bumperbot_ws

source install/setup.bash

Run:

ros2 launch bumperbot_controller controller.launch.py --show-args

OUTPUT

'use_sim_time':
    no description given
    (default: 'True')

'use_simple_controller':
    no description given
    (default: 'True')

'wheel_radius':
    no description given
    (default: '0.033')

'wheel_separation':
    no description given
    (default: '0.17')

These arguments allow us to select the controller and configure the robot's wheel dimensions.

Launch the Diff Drive Controller

By default, our launch file uses the custom Python Simple Controller.

Now, we want to use the built-in Diff Drive Controller.

To do this, set:

use_simple_controller = false

Open a new terminal, source the workspace, and run:

. install/setup.bash
ros2 launch bumperbot_controller controller.launch.py use_simple_controller:=false

his time, the launch file will:

  • Start the Joint State Broadcaster.
  • Start the built-in bumperbot_controller.
  • Skip the custom Python Simple Controller.
  • Skip the Simple Velocity Controller spawner.

The controller manager will load the Diff Drive Controller using the configuration we added to bumperbot_controllers.yaml.

Connect and Launch the Joystick

We can now use the same physical joystick that we configured in the previous chapter.

Connect your joystick to the computer using USB or a supported wireless connection.

In this demonstration, we are using the HyperX Clutch Gladiate controller.

Open another terminal:

. install/setup.bash

Launch the joystick teleoperation system:

ros2 launch bumperbot_controller joystick_teleop.launch.py

This starts:

  • The joy_node, which reads the physical joystick inputs.
  • The joy_teleop node, which converts joystick inputs into velocity commands.

The joystick publishes TwistStamped commands to the same robot velocity topic used in the previous chapter.

Teleoperate the BumperBot

Once the joystick has been detected, we can start controlling the robot.

Just like in the previous chapter, keep the deadman button pressed while using the joystick's analog controls.

Use the configured controls to:

  • Move the robot forward and backward.
  • Turn the robot left and right.
  • Combine forward movement and turning.

What Happens Internally?

This time, the joystick commands are processed directly by the built-in Diff Drive Controller.

The data flow is:

Physical Joystick
|
v
Joy Node
|
v
Joy Teleop Node
|
v
/bumperbot_controller/cmd_vel
|
v
Diff Drive Controller
|
v
Differential Kinematics
|
v
Individual Wheel Speeds
|
v
BumperBot Wheel Motion
|
v
Gazebo Simulation

The movement should be very similar to what we observed with our custom Python Simple Controller.

The main difference is that the velocity conversion is now handled by the built-in Diff Drive Controller instead of our own Python implementation.
