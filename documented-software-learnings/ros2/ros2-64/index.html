Wheel Odometry: x, y and theta in the Simple Controller

Introduction

In chapter 62 the node simple_controller learned to measure how the robot really moves. It reads the wheel angles on the joint_states topic, works out how far each wheel turned (dp) and how much time passed (dt), and logs the driving speed linear and the turning speed angular. Chapter 63 then showed the idea behind odometry: a distance is a speed added up over many tiny pieces of time (the ∫ sign), and an angle works the same way.

This chapter puts that idea into code. The node now keeps the robot's pose, three numbers that say where the robot is and which way it faces:

  • x_: how far the robot is in front of its starting point, in metres,
  • y_: how far it is to the left of its starting point, in metres,
  • theta_: the direction it faces, in radians.

With every joint_states message the node works out one small step, how far the robot moved (d_s) and how much it turned (d_theta), and adds the step to x, y and theta. Then it logs the three numbers, so they can be watched changing while the robot turns and drives in Gazebo.

The node from chapter 62 must already build and run, with the Gazebo simulation and the controller launch file. This chapter only changes simple_controller.py. It needs no new dependency, because math is part of Python itself (as far as I know).

The formulas

Every letter first, then the formulas:

LetterMeaningValue here
rwheel radius0.033 m
swheel separation (distance between the two wheels)0.17 m
Δφ (dp_left, dp_right in the code)how far a wheel turned since the last reading: new angle minus old anglein rad
Δs (d_s)how far the robot moved forward in this reading: (r × ΔφR + r × ΔφL) ÷ 2in m
Δθ (d_theta)how much the robot turned in this reading: (r × ΔφR minus r × ΔφL) ÷ sin rad
θ (theta_)the heading: the old θ plus Δθin rad
x (x_)the old x plus Δs × cos θin m
y (y_)the old y plus Δs × sin θin m

Δs and Δθ have the same shape as V and ω of chapter 62, but with Δφ in place of φ̇. Speed × time = distance, and φ̇ × Δt = Δφ, so Δt cancels: the step comes straight from dp, with no division by time. The new θ is used for x and y, so the line that adds to theta comes first.

Writing the code

Open the file

In VS Code, open src, then the bumperbot_controller package folder, then the bumperbot_controller folder inside it, and open simple_controller.py.

The code

The whole node, with the new odometry lines added to the node of chapter 62:

#!/usr/bin/env python3

import rclpy
from rclpy.node import Node
from std_msgs.msg import Float64MultiArray
from geometry_msgs.msg import TwistStamped
from sensor_msgs.msg import JointState
import numpy as np
from rclpy.time import Time
from rclpy.constants import S_TO_NS
import math


class SimpleController(Node):

    def __init__(self):
        super().__init__("simple_controller")

        self.declare_parameter("wheel_radius", 0.033)
        self.declare_parameter("wheel_separation", 0.17)

        self.wheel_radius_ = self.get_parameter("wheel_radius").get_parameter_value().double_value
        self.wheel_separation_ = self.get_parameter("wheel_separation").get_parameter_value().double_value

        self.get_logger().info("Using wheel radius %f" % self.wheel_radius_)
        self.get_logger().info("Using wheel separation %f" % self.wheel_separation_)

        self.left_wheel_prev_pos_ = 0.0
        self.right_wheel_prev_pos_ = 0.0
        self.prev_time_ = None   # set from the first joint_states message

        self.x_ = 0.0
        self.y_ = 0.0
        self.theta_ = 0.0

        self.wheel_cmd_pub_ = self.create_publisher(Float64MultiArray, "simple_velocity_controller/commands", 10)
        self.vel_sub_ = self.create_subscription(TwistStamped, "bumperbot_controller/cmd_vel", self.velCallback, 10)
        self.joint_sub_ = self.create_subscription(JointState, "joint_states", self.jointCallback, 10)

        self.speed_conversion_ = np.array([[self.wheel_radius_/2, self.wheel_radius_/2],
                                           [self.wheel_radius_/self.wheel_separation_, -self.wheel_radius_/self.wheel_separation_]])
        self.get_logger().info("The conversion matrix is %s" % self.speed_conversion_)

    def velCallback(self, msg):
        robot_speed = np.array([[msg.twist.linear.x],
                                [msg.twist.angular.z]])

        wheel_speed = np.matmul(np.linalg.inv(self.speed_conversion_), robot_speed)

        wheel_speed_msg = Float64MultiArray()
        wheel_speed_msg.data = [wheel_speed[1, 0], wheel_speed[0, 0]]

        self.wheel_cmd_pub_.publish(wheel_speed_msg)

    def jointCallback(self, msg):
        now = Time.from_msg(msg.header.stamp)

        # First message, or sim time went backwards (e.g. sim reset): re-seed
        if self.prev_time_ is None or now < self.prev_time_:
            self.left_wheel_prev_pos_ = msg.position[0]
            self.right_wheel_prev_pos_ = msg.position[1]
            self.prev_time_ = now
            return

        dt = (now - self.prev_time_).nanoseconds / S_TO_NS
        if dt == 0.0:   # duplicate stamp
            self.get_logger().warn("Skipping joint state: duplicate stamp",
                                throttle_duration_sec=2.0)
            return

        dp_left = msg.position[0] - self.left_wheel_prev_pos_
        dp_right = msg.position[1] - self.right_wheel_prev_pos_

        self.left_wheel_prev_pos_ = msg.position[0]
        self.right_wheel_prev_pos_ = msg.position[1]
        self.prev_time_ = now

        fi_left = dp_left / dt
        fi_right = dp_right / dt

        linear = (self.wheel_radius_ * fi_right + self.wheel_radius_ * fi_left) / 2
        angular = (self.wheel_radius_ * fi_right - self.wheel_radius_ * fi_left) / self.wheel_separation_

        d_s = (self.wheel_radius_ * dp_right + self.wheel_radius_ * dp_left) / 2
        d_theta = (self.wheel_radius_ * dp_right - self.wheel_radius_ * dp_left) / self.wheel_separation_
        self.theta_ += d_theta
        self.x_ += d_s * math.cos(self.theta_)
        self.y_ += d_s * math.sin(self.theta_)

        self.get_logger().info("linear: %f, angular: %f" % (linear, angular))
        self.get_logger().info("x: %f, y: %f, theta: %f" % (self.x_, self.y_, self.theta_))

def main():
    rclpy.init()

    simple_controller = SimpleController()
    rclpy.spin(simple_controller)

    simple_controller.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()

What is new

  • Line 11: import math, for math.cos and math.sin.
  • Lines 32 to 34: the pose. x_, y_ and theta_ all start at 0.0: the robot is at the origin and faces forward.
  • Lines 84 and 85: the step of this reading: d_s, how far the robot moved, and d_theta, how much it turned. Both are made from dp_left and dp_right.
  • Lines 86 to 88: the adding up. theta_ grows by d_theta, then x_ grows by d_s times the cosine of the heading and y_ by d_s times its sine.
  • Line 91: a second log line that prints x, y and theta.

Everything else is the node of chapter 62, unchanged (lines 55 to 82 are its jointCallback: the first-message check, dt, dp, the speeds).

One reading with real numbers

The last test of this chapter, driving and turning at the same time (linear x 0.5 and angular z 0.5), has the most to show, so here is one reading worked out by hand. The controller makes the right wheel turn at (0.5 + 0.5 × 0.17 ÷ 2) ÷ 0.033 = 16.4394 rad/s and the left wheel at (0.5 minus 0.5 × 0.17 ÷ 2) ÷ 0.033 = 13.8636 rad/s. The "before" values for theta, x and y are read from a line of the log on the screen (the screenshots below).

  1. dp (lines 71 and 72): in 10 ms the right wheel turns 16.4394 × 0.01 = 0.164394 rad and the left wheel 13.8636 × 0.01 = 0.138636 rad.
  2. d_s (line 84): r × dp_right = 0.033 × 0.164394 = 0.005425 m and r × dp_left = 0.033 × 0.138636 = 0.004575 m. So d_s = (0.005425 + 0.004575) ÷ 2 = 0.01 ÷ 2 = 0.005 m.
  3. d_theta (line 85): (0.005425 minus 0.004575) ÷ 0.17 = 0.00085 ÷ 0.17 = 0.005 rad.
  4. theta (line 86): the log shows theta = 198.525000 before, so theta = 198.525 + 0.005 = 198.530 rad.
  5. cos and sin (lines 87 and 88): 198.530 rad is 31 full turns plus 3.7513 rad (a full turn is 2π = 6.2832 rad), and cos and sin repeat after every full turn. cos(198.530) = -0.819841 and sin(198.530) = -0.572591.
  6. x (line 87): x = -0.652450 + 0.005 × (-0.819841) = -0.652450 + (-0.004099) = -0.656549 m.
  7. y (line 88): y = 1.817925 + 0.005 × (-0.572591) = 1.817925 + (-0.002863) = 1.815062 m.

The next log line of the test shows x: -0.656549, y: 1.815062 and theta: 198.530000: the same numbers. The widget below does the same sum for other readings of the screenshots. Tick "use the old theta" and the result is off by about 0.00002: with the old heading (198.525) x would come out as -0.656563, which is not what the screen shows. So the node really does use the new theta, and line 86 must stay above lines 87 and 88.

Why 0.005? The wheels turn equally fast in opposite directions, so d_s = 0 and d_theta = (0.033 × 0.012879 minus 0.033 × (-0.012879)) ÷ 0.17 = 0.00085 ÷ 0.17 = 0.005 rad per reading (0.5 rad/s × 0.01 s). That is why x and y do not change: d_s is 0, so d_s × cos and d_s × sin are 0 too. And 152.22 is such a big number because theta is never wrapped back into the range minus π to π: 152.22 rad is about 24 full turns of the test so far (152.22 ÷ 6.2832 = 24.2). The cos and sin of lines 87 and 88 repeat after every full turn, so this does not matter for x and y.

Pick one of the three commands and drag the reading slider: the picture shows the path, the heading and the lines that terminal 3 would print, with the working for the last reading.

Remember

  • The pose is three numbers on the node: x_ and y_ in metres and theta_ in radians. They all start at 0.0 when the node starts.
  • One reading gives one small step: d_s = (r × dp_right + r × dp_left) ÷ 2 for the way forward, and d_theta = (r × dp_right minus r × dp_left) ÷ s for the turn. They use dp, not the speeds, so dt cancels.
  • Add up in this order: theta_ += d_theta first, then x_ += d_s * math.cos(theta_) and y_ += d_s * math.sin(theta_). Use +=, not =, and give cos and sin radians.
  • Turning left on the spot raises theta by 0.005 per reading (0.5 rad/s × 0.01 s), turning right lowers it, and x and y stay put because d_s is 0. With V = 0.5 and ω = 0.5 the robot drives a circle of radius V ÷ ω = 1 m.
  • Theta is never wrapped, so it can show values such as 152.22. cos and sin repeat every full turn, so x and y are still right.
  • The first message only stores the "before" values, so the pose starts to change from the second message. A repeated stamp (dt = 0) is skipped.
  • Odometry only adds up small steps, so a small error in the wheel radius or the wheel separation grows with the distance driven (chapter 60), and the node starts at (0, 0, 0) wherever the robot is.
