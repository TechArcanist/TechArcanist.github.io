Simple TF2 Broadcaster: Static and Dynamic Transforms

Introduction

In the previous lesson we published a static transform between two frames with the StaticTransformBroadcaster class. Now we add a second feature to the same Python node: it will also publish a dynamic transform, one that changes over time.

We keep working in the bumperbot_py_examples package and in the SimpleTfKinematics class. By the end of this lesson the node publishes two things:

  • Static: bumperbot_base to bumperbot_top, 0.3 m up, sent once on /tf_static.
  • Dynamic: odom to bumperbot_base, sent every 0.1 s on /tf, with the base moving 0.05 m forward each time.

Open the Python file

In the workspace, open src, then the bumperbot_py_examples package folder, then the inner bumperbot_py_examples folder, and open simple_tf_kinematics.py.

Write the code

What is new compared with the static version

  • A second broadcaster, TransformBroadcaster, for transforms that change (lines 4 and 14).
  • A second message, dynamic_transform_stamped_, for the moving transform (line 17).
  • Two helper numbers: the step x_increment_ (0.05 m) and the last known position last_x_ (lines 19 and 20).
  • A ROS 2 timer that calls timerCallback every 0.1 s (line 41), and the callback itself (lines 43 to 58).

The full file

Update simple_tf_kinematics.py so it looks like this:

import rclpy
from rclpy.node import Node
from tf2_ros.static_transform_broadcaster import StaticTransformBroadcaster
from tf2_ros import TransformBroadcaster
from geometry_msgs.msg import TransformStamped


class SimpleTfKinematics(Node):

    def __init__(self):
        super().__init__("simple_tf_kinematics")

        self.static_tf_broadcaster_ = StaticTransformBroadcaster(self)
        self.dynamic_tf_broadcaster_ = TransformBroadcaster(self)

        self.static_transform_stamped_ = TransformStamped()
        self.dynamic_transform_stamped_ = TransformStamped()

        self.x_increment_ = 0.05
        self.last_x_ = 0.0

        self.static_transform_stamped_.header.stamp = self.get_clock().now().to_msg()
        self.static_transform_stamped_.header.frame_id = "bumperbot_base"
        self.static_transform_stamped_.child_frame_id = "bumperbot_top"
        self.static_transform_stamped_.transform.translation.x = 0.0
        self.static_transform_stamped_.transform.translation.y = 0.0
        self.static_transform_stamped_.transform.translation.z = 0.3
        self.static_transform_stamped_.transform.rotation.x = 0.0
        self.static_transform_stamped_.transform.rotation.y = 0.0
        self.static_transform_stamped_.transform.rotation.z = 0.0
        self.static_transform_stamped_.transform.rotation.w = 1.0

        self.static_tf_broadcaster_.sendTransform(self.static_transform_stamped_)

        self.get_logger().info("Publishing static transform between %s and %s" %
                      (
                        self.static_transform_stamped_.header.frame_id,
                        self.static_transform_stamped_.child_frame_id
                      ))

        self.timer_ = self.create_timer(0.1, self.timerCallback)

    def timerCallback(self):
        self.dynamic_transform_stamped_.header.stamp = self.get_clock().now().to_msg()
        self.dynamic_transform_stamped_.header.frame_id = "odom"
        self.dynamic_transform_stamped_.child_frame_id = "bumperbot_base"
        self.dynamic_transform_stamped_.transform.translation.x = self.last_x_ + self.x_increment_
        self.dynamic_transform_stamped_.transform.translation.y = 0.0
        self.dynamic_transform_stamped_.transform.translation.z = 0.0
        self.dynamic_transform_stamped_.transform.rotation.x = 0.0
        self.dynamic_transform_stamped_.transform.rotation.y = 0.0
        self.dynamic_transform_stamped_.transform.rotation.z = 0.0
        self.dynamic_transform_stamped_.transform.rotation.w = 1.0



        self.dynamic_tf_broadcaster_.sendTransform(self.dynamic_transform_stamped_)
        self.last_x_ = self.dynamic_transform_stamped_.transform.translation.x


def main():
    rclpy.init()

    simple_tf_kinematics = SimpleTfKinematics()
    rclpy.spin(simple_tf_kinematics)

    simple_tf_kinematics.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()

How the code works

Two broadcasters

To publish a static transform we used StaticTransformBroadcaster. To publish a dynamic transform we use a TransformBroadcaster object instead, also from the tf2_ros library. It is created as a member of the class (line 14) and, like the static one, receives the current object self as input.

The moving transform also needs its own message, again a TransformStamped: dynamic_transform_stamped_ on line 17.

The helper numbers

x_increment_ (line 19) is how much the transform moves on every timer tick: 0.05 m. last_x_ (line 20) holds the last known value of the translation along x, used to calculate the next position. Nothing has been published yet, so it starts at 0.0.

The timer

To publish the dynamic transform again and again, and so simulate the movement between two frames, we use a ROS 2 timer. create_timer, inherited from the Node class, gets a period of 0.1 s and the function to run when the timer expires: self.timerCallback, written without brackets so the timer can call it later (line 41).

The timer only fires while rclpy.spin is running (line 65). That is when the moving transform starts to be published.

The timer callback

Every time the timer expires, timerCallback (lines 43 to 58) fills the message and publishes it:

  • Time stamp: the current ROS time, the same instruction we used for the static transform (line 44).
  • Parent and child: the parent frame is a new frame called odom and the child is bumperbot_base (lines 45 and 46).
  • Translation: x is the last position plus the increment, last_x_ + x_increment_. y and z stay 0 (lines 47 to 49).
  • Rotation: the quaternion (0, 0, 0, 1), so odom and bumperbot_base are oriented the same way (lines 50 to 53).
  • Publish: sendTransform on the dynamic broadcaster sends the message on /tf (line 57).
  • Remember: last_x_ is updated to the x that was just sent, so the next tick continues from there (line 58).

With a step of 0.05 m every 0.1 s, the base moves forward at 0.5 m per second.

The frame tree

The static transform connects the parent bumperbot_base to the child bumperbot_top. The dynamic transform connects the new parent odom to bumperbot_base. So odom is the root of the tree, bumperbot_base is its child, and bumperbot_base is at the same time the parent of bumperbot_top.

Explanation

Use the interactive visualizer below to walk through the code line by line, see how the pieces connect, step through a run with the timer ticking, try common bugs, and follow the build and run steps.

Build and Run

Build the workspace

Open a terminal and go to the workspace:

cd bumperbot_ws

Then build it:

colcon build

Wait for the build to finish successfully.

Set up RViz 2

Before starting the node, open RViz 2 in another terminal:

rviz2

In RViz 2, click the Fixed Frame field under Global Options and change it to odom, the first frame of our tree.

Then click Add and add the TF display.

Run the node

Open another terminal and source the workspace:

. install/setup.bash

Then start the node:

ros2 run bumperbot_py_examples simple_tf_kinematics

What you should see

RViz 2 now shows three frames. odom is fixed, while bumperbot_base and bumperbot_top move: bumperbot_base keeps translating along the x axis of odom. The transform between bumperbot_base and bumperbot_top stays static, so the top does not move relative to the base. They move together, as if they were screwed together.

In RViz 2 we are seeing both transforms at the same time: the static one from /tf_static and the dynamic one from /tf, which changes over time.
