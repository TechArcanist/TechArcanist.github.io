Localization with Kalman Filter

Introduction

Chapter 77 wrote the Kalman filter node, kalman_filter.py. It estimates one number, the angular velocity of the robot around z, by fusing two sources: the noisy wheel odometry on bumperbot_controller/odom_noisy and the IMU on imu/out. The result goes out as a new Odometry message on bumperbot_controller/odom_kalman (chapter 77, Introduction).

This chapter starts the node and checks whether it does its job. The simulation, the controllers and the filter run together, and PlotJuggler draws three angular velocities on one graph: the perfect one, the noisy one and the filtered one. The filtered line should stay much closer to the perfect one, first with the robot standing still and then while it turns with the joystick.

What must already work

  • The workspace is built with kalman_filter.py in it (chapter 77, Build the workspace), so no new build is needed here.
  • The Gazebo simulation, controller.launch.py with the noisy controller, and PlotJuggler work as in chapters 70 and 71.
  • A joystick is connected to the PC before the teleop is started.

Starting the robot and the filter

Every terminal below is a new terminal, and each one first loads the workspace with . install/setup.bash from inside bumperbot_ws.

Terminal 1: the simulation

Go to the workspace:

cd bumperbot_ws

Load the workspace:

. install/setup.bash

Start the empty Gazebo world with the robot:

ros2 launch bumperbot_description gazebo.launch.py

What you should see

[INFO] [launch]: All log files can be found below /home/techarcanist/.ros/log/2026-11-28-14-11-02-993105-omen-6202
[INFO] [launch]: Default logging verbosity is set to INFO
[INFO] [robot_state_publisher-1]: process started with pid [6207]

Terminal 2: the controllers and the noisy odometry

Load the workspace in a new terminal:

. install/setup.bash

Start the control system with the diff drive controller instead of the simple controller:

ros2 launch bumperbot_controller controller.launch.py use_simple_controller:=false

What you should see

[INFO] [launch]: Default logging verbosity is set to INFO
[INFO] [spawner-1]: process started with pid [7143]
[INFO] [spawner-2]: process started with pid [7144]
[INFO] [noisy_controller.py-3]: process started with pid [7145]

This one launch file starts three things that matter here:

  • the controller that receives the speed commands and turns the wheels, here the diff drive controller because use_simple_controller is false;
  • the perfect odometry, without noise, on bumperbot_controller/odom;
  • the noisy odometry of noisy_controller on bumperbot_controller/odom_noisy, the one the Kalman filter has to improve (its process shows in the log above).

The launch file has a second argument, use_python, which picks the Python or the C++ version of the controller nodes. The log shows noisy_controller.py, the Python node of chapter 69. Changing the value of that argument switches the implementation.

Terminal 3: the Kalman filter

Load the workspace in a new terminal:

. install/setup.bash

Start the filter node of chapter 77 from the bumperbot_localization package:

ros2 run bumperbot_localization kalman_filter.py

What you should see

(no output: the node runs silently and the prompt does not come back)

The node takes two inputs, the noisy odometry and the IMU measurement from the simulated IMU in Gazebo, fuses them to estimate the angular velocity better, and publishes the result on bumperbot_controller/odom_kalman. The .py suffix runs the Python node; as far as I know a C++ version of the same filter would be run by its name without the suffix.

Check the topics

To see the new topic, list all the topics from any sourced terminal:

ros2 topic list

What you should see

...
/bumperbot_controller/odom
/bumperbot_controller/odom_kalman
/bumperbot_controller/odom_noisy
...
/imu/out
...

The list is approximate: only the lines that matter are shown. There are three odometry topics: odom (perfect, no noise), odom_noisy (the noisy wheels) and odom_kalman (the filter).

Plotting the three angular velocities

Terminal 4: PlotJuggler

Load the workspace in a new terminal:

. install/setup.bash

Start PlotJuggler (installed in chapter 71):

ros2 run plotjuggler plotjuggler

What you should see

QMetaObject::connectSlotsByName: No matching signal for on_buttonCloseStatus_clicked()
Loading compatible plugins from directory:  "/opt/ros/jazzy/lib/plotjuggler_ros"

Subscribe to the three odometry topics

  1. In Streaming, pick ROS2 Topic Subscriber and press Start.
  2. In the list of topics, select /bumperbot_controller/odom, /bumperbot_controller/odom_kalman and /bumperbot_controller/odom_noisy.
  3. Press OK.

Drag the angular velocity of each topic

The path in the Timeseries list is the same for all three, as in chapter 71, only now it ends at the angular velocity instead of the linear one. For each topic open twist, then twist again, then angular, and drag z into the graph:

  • odom → twist → twist → angular → z (the perfect value)
  • odom_kalman → twist → twist → angular → z (the filtered value)
  • odom_noisy → twist → twist → angular → z (the noisy value)

What the graph shows with the robot still

The robot is stopped, so the perfect angular velocity on odom is 0. The noisy one jumps around a lot, because noise was added to the wheel readings on purpose in chapter 69. The filtered one is much cleaner: its error is far smaller than the error of the noisy odometry, and it stays much closer to the ground truth. The filter gets there by using both pieces of information, the noisy wheels and the IMU.

The widget below runs the same loop as kalman_filter.py, with the variances of chapter 77 (motion 4.0, IMU 0.5), on made-up noisy readings. It shows the working of every round.

Driving the robot

Terminal 5: the joystick

Connect the joystick to the PC first (the same teleop as in chapter 71). Then load the workspace in a new terminal:

. install/setup.bash

Start the joystick teleop:

ros2 launch bumperbot_controller joystick_teleop.launch.py

What you should see

(the joystick is recognised and the robot answers to it; the exact log lines were not captured)

Turn the robot and watch the lines

Keep Gazebo on one side of the screen and PlotJuggler on the other, and rotate the robot with the joystick. While it turns, the filtered angular velocity is again more accurate than the noisy one: it stays closer to the real value from the perfect odometry.

Remember

  • Five terminals: Gazebo, controller.launch.py with use_simple_controller:=false (diff drive controller, perfect odometry and noisy odometry), the Kalman filter with ros2 run bumperbot_localization kalman_filter.py, PlotJuggler, and the joystick teleop.
  • There are three odometry topics: odom (perfect, no noise), odom_noisy (noise added on purpose) and odom_kalman (the filter).
  • The filter fuses the noisy wheel odometry and the IMU on imu/out to estimate the angular velocity around z.
  • In PlotJuggler the path is odom → twist → twist → angular → z for each topic.
  • Still or turning, the filtered angular velocity is much closer to the true value than the noisy one.
  • This is a Bayes filter in its simplest form, the Kalman filter, fusing noisy data from different sensors into a better estimate. So far it estimates only the angular velocity; next it is extended to the full odometry message, with the linear and the angular velocity.
